# ТСПУ, обфускация и что делать, когда «не работает»

## Коротко

| Что случилось | Симптом | Что делать |
|---|---|---|
| Один порт зарезан | клиент перебрал порты, ни один не ответил | `cli.js ports` — добавить/сменить порты |
| Сигнатура AmneziaWG примелькалась | handshake не проходит на всех портах | `cli.js reseed`, перезапуск |
| UDP у провайдера задушен полностью | не работает ни один порт | ждать / сменить провайдера / TCP-транспорт (в планах) |
| TCP-блокировки, UDP жив | всё работает | ничего, это как раз наш случай |

## Почему не голый WireGuard

ТСПУ смотрит на сигнатуры: фиксированный заголовок `type: 1..4` в первых байтах
UDP-датаграммы, характерные размеры (148/92 байта на рукопожатии), стабильный
интервал `PersistentKeepalive`. По этим признакам WireGuard узнаётся с первого
пакета и блокируется целиком — независимо от порта и содержимого.

AmneziaWG меняет именно внешние признаки:

- `Jc/Jmin/Jmax` — количество и размер случайных junk-пакетов перед рукопожатием;
- `S1/S2` — случайный паддинг служебных пакетов;
- `H1..H4` — свои значения типов сообщений вместо `1..4`.

По умолчанию у AmneziaWG тоже есть «дефолтный» набор параметров, который уже
примелькался фильтрам. Поэтому здесь параметры **генерируются случайно для
каждой установки**, а не берутся из примера в документации.

## Порт

- Основной порт выбирается случайным из 20000–60000: типовые `51820`, `1194`,
  `500` — первые кандидаты на фильтрацию.
- Пул дополнительных портов (`443`, `500`, `4500`, `8443`) заворачивается в
  основной через `iptables REDIRECT`. Клиент перебирает их сам.
- `443/udp` выглядит как QUIC — самый «легальный» вариант для DPI.
- Если провайдер режет именно UDP/443 из-за QUIC-политики, останутся 500/4500
  (похоже на IPsec) и случайный основной порт.

Проверить, что порт реально слушается и принимает пакеты:

```bash
ss -lunp | grep awg
awg show nurofen0            # latest handshake, transfer
journalctl -u nurofen -f
```

Если в `awg show` у пира есть `latest handshake`, но `transfer` почти нулевой —
пакеты приходят, но ответы теряются: смотрите `ufw`, `iptables -L -n -v` и MTU.

## MTU

По умолчанию 1280 — заведомо безопасное значение для PPPoE/мобильных сетей.
Если большие пакеты теряются (Minecraft «замирает» при входе в мир, файлы
рвутся), уменьшите:

```bash
# /etc/nurofen/nurofen.json → server.mtu = 1200
systemctl restart nurofen
```

В сервер добавлено правило MSS clamping для TCP через туннель, но при
экзотическом PPPoE иногда всё равно нужен запас.

## Порядок действий при блокировке

1. **Проверить, что дело в сети, а не в клиенте.** Пинг хаба из клиента,
   `journalctl -u nurofen`.
2. **Сменить пул портов**: `node src/cli.js ports 443,8443,2053,2087`
   (лучше брать «чужие» популярные порты).
3. **Пересоздать параметры обфускации**: `node src/cli.js reseed` +
   `systemctl restart nurofen`. Все клиенты переподключатся с новыми
   параметрами автоматически.
4. **Проверить с другого оператора.** Мобильный интернет, домашний Wi-Fi,
   другой город — ТСПУ ведут себя по-разному, и «не работает у одного» не значит
   «не работает у всех».
5. **Если UDP мёртв у всех** — нужен TCP-транспорт. В 2026 ТСПУ также научились
   морозить часть TCP-соединений (первые ~16 пакетов проходят, дальше тишина),
   поэтому правильное решение — несколько транспортов с автопереключением, а не
   один «вечный» протокол. См. [ROADMAP.md](ROADMAP.md).

## Чего этот проект не делает

- Не маскирует трафик под HTTPS: обфускация AmneziaWG — это «не похоже на
  WireGuard», а не «неотличимо от браузера».
- Не обещает работу при полном отключении UDP или при белых списках.
- Не скрывает факт использования VPN от вашего провайдера как таковой — только
  конкретный протокол.
