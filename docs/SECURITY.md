# Безопасность

## Модель угроз

Кого защищаем и от чего:

| Угроза | Защита |
|---|---|
| Провайдер/ТСПУ видит протокол и блокирует | AmneziaWG с случайными параметрами, нестандартный порт, пул портов |
| Провайдер видит содержимое трафика | ChaCha20-Poly1305 на уровне AmneziaWG |
| Посторонний подключается к сети | пароль сети хранится как scrypt-хеш; при входе проверяется название и пароль |
| Участник сети сканирует чужие сервисы | отдельная подсеть `/24` на сеть и правила изоляции на сервере |
| Кража конфига с сервера | на сервере нет приватных ключей участников — только публичные |
| Подмена сервера | ключ сервера приходит при `join`; сравнить можно в панели (параметры обфускации тоже) |

Чего **нет**:

- **Нет TLS на API по умолчанию.** Пароль сети, токен устройства и параметры
  идут по HTTP. Кто стоит в разрыве (провайдер, публичный Wi-Fi), может их
  прочитать. Для более строгой защиты поставьте перед сервером Caddy/nginx с
  сертификатом и используйте HTTPS.
- **Нет защиты от компрометации VPS.** Root на сервере = возможность выдавать
  себя за сеть. Ключи участников при этом остаются недоступными (их нет на
  сервере), но поддельные параметры обфускации и адрес хаба злоумышленник может
  раздавать.
- Пароли сетей передаются при входе по API — см. пункт про TLS выше.
- **Нет аудита действий и ротации ключей по расписанию.**

## Что где хранится

| Секрет | Где | Кто читает |
|---|---|---|
| Приватный ключ X25519 участника | `%APPDATA%\Nurofen\client.json` | только пользователь (права `0600`) |
| Токен устройства | там же | только пользователь |
| Публичный ключ участника, IP, хеш токена | `/etc/nurofen/nurofen.json` (`0600`) | root |
| `adminToken` | там же | root |
| Токен службы-помощника | `C:\ProgramData\Nurofen\helper-token` | Users: read, SYSTEM/админы: full |
| Пароль сети | только scrypt-хеш в `/etc/nurofen/nurofen.json` | root (не может прочитать исходный пароль) |

Хеширование: токены устройств хранятся как `sha256`, пароли сетей — как `scrypt`; секреты не отображаются в панели.
Компромисс: приватный ключ участника лежит на диске в открытом виде. Полноценная
защита — DPAPI, это в планах (см. [ROADMAP.md](ROADMAP.md)).

## Что делает служба-помощник

Служба `NurofenHelper` работает от LocalSystem и принимает HTTP-запросы **только
с loopback** (`127.0.0.1`/`::1`) и **только с токеном** из `helper-token`.
Разрешённые операции:

- `POST /tunnel/up` — записать конфиг в `C:\ProgramData\Nurofen\conf` и вызвать
  `amneziawg.exe /installtunnelservice`;
- `POST /tunnel/down`;
- `GET /tunnel/status`;
- `POST /awg/install` — установить AmneziaWG, если его нет.

Имя туннеля ограничено `^[a-z0-9-]{1,32}$`, конфиг обязан содержать секции
`[Interface]` и `[Peer]`. Произвольные команды не исполняются.

Риск: локальный пользователь, прочитавший `helper-token`, может поднять в системе
произвольный WireGuard-туннель. Это осознанный компромисс: токен читается всеми
пользователями машины, зато клиент не требует UAC. На общих машинах это
нежелательно — можно ужесточить ACL до конкретного пользователя.

## Передачи файлов и удалённая помощь

Обе функции работают напрямую между участниками сети через туннель, без
интернет-сервера:

- получатель должен быть онлайн-участником подключённой сети, а его адрес
  сверяется с текущим списком — посторонний с другим IP не пройдёт;
- запрос содержит одноразовый токен и не принимается автоматически: файл
  начинается только после «Принять», экран — только после «Разрешить»;
- удалённая помощь дополнительно требует явного согласия на управление. Оно
  выключено по умолчанию, включается на принимающей стороне и отключается на
  лету; ввод не передаётся, пока управление запрещено;
- активный сеанс виден индикатором, любая сторона может его остановить;
- входящую помощь можно запретить целиком в настройках, тогда клиент отвечает
  отказом;
- файлы принимаются на TCP `39395–39397`, экран — на `39398–39399`; оба
  диапазона разрешены брандмауэром только из подсети Nurofen.

## Рекомендации

1. Передавайте пароль сети только участникам, которым нужен доступ; при утечке
   смените его через админ-панель.
2. Не публикуйте `adminToken`, не храните его в репозитории.
3. Отключайте ушедших участников через панель — это удаляет пир из интерфейса
   сразу, а не «когда-нибудь».
4. Держите VPS обновлённым (`unattended-upgrades`), не ставьте лишнего.
5. Для публичной сети включите TLS перед API.

## Сообщить о проблеме

Откройте issue с описанием: версия (в панели клиента), ОС, оператор связи,
вывод «Диагностики». Без токенов и ключей.
