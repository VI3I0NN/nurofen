# Архитектура

## Компоненты

| Компонент | Где живёт | Что делает |
|---|---|---|
| `nurofen.service` | VPS, systemd | API, учёт устройств, рендер конфигов, управление интерфейсом AmneziaWG |
| `nurofen0` | VPS, ядро | Единый AmneziaWG-интерфейс для подсетей пользовательских сетей внутри `10.66.0.0/16` |
| `NurofenHelper` | Windows, служба | Поднимает/опускает туннель по запросу клиента (нужны права SYSTEM) |
| Клиент | Windows, процесс пользователя | Окно Electron, локальная панель `127.0.0.1:39391`, трей, перебор портов, пинг, поиск порта Minecraft |

Клиент специально не требует прав администратора: единственная операция, которой
нужны права, — установка службы туннеля, и она делегирована службе-помощнику.
Общение идёт по loopback с токеном из `C:\ProgramData\Nurofen\helper-token`
(доступ на чтение у группы Users, на запись — только у SYSTEM/администраторов).

## Топология: звезда, а не mesh

Все клиенты подключаются к хабу на VPS. У хаба есть адрес `.1` в каждой
пользовательской сети, и он форвардит пакеты только внутри этой сети:
`A → хаб → B` для участников одной сети, между сетями пересылки нет.

Почему звезда:

- один публичный адрес, не нужно раскрывать адреса участников;
- работает за NAT у всех сторон;
- проще диагностировать (один endpoint);
- цена — +RTT до VPS и трафик через сервер.

Для Minecraft это незаметно, если VPS в Европе: 30–60 мс.

## Поток создания и подключения

Все клиенты используют один адрес VPS. Создатель отправляет название и пароль с
`mode: create`; участник отправляет их с `mode: join`. Пароли сетей сохраняются
только в виде scrypt-хеша.

```
клиент                     сервер                         ядро
  │  POST /api/v1/join       │
  │  {mode, name, password, pubkey}
  ├─────────────────────────►│  создаёт или находит сеть по имени
  │                          │  проверяет пароль, выделяет IP в её /24
  │                          │  awg set peer <pub> allowed-ips <ip>/32
  │◄─────────────────────────┤  {token, network, ip, awgPubKey, ports}
  │                          │
  │  генерирует conf и поднимает туннель через службу-помощник
  │  получает маршрут только до своей подсети
  │  POST /api/v1/heartbeat  │
  ├─────────────────────────►│  lastSeen и список пиров только своей сети
```

`join` идемпотентен по `deviceId`: повторный вход тем же устройством переиспользует слот.

## Игра по сети

Broadcast в L3-сети не проходит, поэтому игра «для сети» не появляется в списке
сама. Адрес участника виден в клиенте — его копируют кнопкой рядом с именем и
вводят в игре вручную (`10.66.<сеть>.N`, порт — тот, что открыла игра). Сервер для
этого не нужен: обмен идёт напрямую по туннелю.

Поле `lanPort` в API и панели осталось для совместимости старых профилей, но
клиент его больше не заполняет.

## Адресация и изоляция

- Пространство сетей сервера — `10.66.0.0/16`, поделённое на `/24`.
- Каждая пользовательская сеть получает отдельную `/24`; адрес `.1` в ней — хаб,
  `.2–9` зарезервированы, `.10–254` выдаются устройствам.
- Клиент получает адрес `/24` и `AllowedIPs` только своей сети.
- На сервере правила iptables запрещают пересылку между пользовательскими
  подсетями, сохраняя связь между устройствами одной сети и с её хабом.

## UDP-порты и обфускация

AmneziaWG слушает один порт (`server.awgPort`, выбирается случайным при
установке). Дополнительные порты из `server.portPool` (`443`, `500`, `4500`,
`8443`) заворачиваются на основной через `iptables -t nat`:

```
PREROUTING → NUROFEN_PORTS → REDIRECT --to-ports <awgPort>
```

Клиент перебирает адреса по порядку (`lastPort`, затем пул) и останавливается на
первом, где прошёл ping хаба. Так блокировка одного порта стоит одного лишнего
переподключения, а не всей сети.

Параметры обфускации (`Jc/Jmin/Jmax/S1/S2/H1..H4`) генерируются случайно при
создании конфига сервера: одинаковых установок не бывает, сигнатура одной не
работает против другой. Пересоздать: `node src/cli.js reseed` + перезапуск.

## Хранение состояния

`/etc/nurofen/nurofen.json` — единственный источник правды: токен админа, ключи
сервера, параметры обфускации, сети (имя, подсеть, scrypt-соль и хеш пароля),
устройства (публичные ключи, IP, хеши токенов). Файл пишется атомарно
(tmp + rename), режим `0600`.

Сгенерированный `nurofen0.conf` перезаписывается сервером при каждом изменении
состава устройств, чтобы после перезагрузки интерфейс поднялся с актуальным
списком пиров.

## API

Публичное (по токену устройства):

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/join` | создание сети или вход по названию и паролю |
| GET | `/api/v1/state` | список участников, статус туннеля |
| POST | `/api/v1/heartbeat` | отметка «я жив» + порт открытого мира (`lanPort`) |
| POST | `/api/v1/key` | смена публичного ключа |
| POST | `/api/v1/devices` | добавить ещё одно устройство в свою сеть (совместимость) |
| POST | `/api/v1/leave` | выйти и освободить адрес |

Админское (по `adminToken`):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/admin/overview` | сводка для панели |
| POST | `/api/v1/admin/networks` | создать сеть |
| DELETE | `/api/v1/admin/networks/:id` | удалить сеть и отключить её устройства |
| POST | `/api/v1/admin/networks/:id/password` | сменить пароль сети |
| DELETE | `/api/v1/admin/peers/:id` | отключить устройство |
| POST | `/api/v1/admin/awg/restart` | перезапустить интерфейс |

`join` ограничен 20 попытками в минуту с одного IP. Названия уникальны без учёта
регистра; сервер хранит только scrypt-хеш пароля каждой сети.

## Почему без зависимостей

Сервер и клиент используют только стандартную библиотеку Node.js. Это значит:
`git clone` + `node src/index.js` вместо `npm install`, нет supply-chain риска на
сервере, который держит ключи, и обновление — это `git pull`.
