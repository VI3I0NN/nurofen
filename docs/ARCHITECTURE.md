# Архитектура

## Компоненты

| Компонент | Где живёт | Что делает |
|---|---|---|
| `nurofen.service` | VPS, systemd | API, учёт устройств, рендер конфигов, управление интерфейсом AmneziaWG |
| `nurofen0` | VPS, ядро | Интерфейс AmneziaWG, хаб виртуальной сети `10.66.0.0/24` |
| `NurofenHelper` | Windows, служба | Поднимает/опускает туннель по запросу клиента (нужны права SYSTEM) |
| Клиент | Windows, процесс пользователя | Локальная панель `127.0.0.1:39391`, трей, перебор портов, пинг, поиск порта Minecraft |

Клиент специально не требует прав администратора: единственная операция, которой
нужны права, — установка службы туннеля, и она делегирована службе-помощнику.
Общение идёт по loopback с токеном из `C:\ProgramData\Nurofen\helper-token`
(доступ на чтение у группы Users, на запись — только у SYSTEM/администраторов).

## Топология: звезда, а не mesh

Все клиенты подключаются к хабу на VPS. Хаб включён в ту же подсеть и форвардит
пакеты между участниками (`net.ipv4.ip_forward=1`), поэтому `A → B` идёт через
VPS: `A → хаб → B`.

Почему звезда:

- один публичный адрес, не нужно раскрывать адреса участников;
- работает за NAT у всех сторон;
- проще диагностировать (один endpoint);
- цена — +RTT до VPS и трафик через сервер.

Для Minecraft это незаметно, если VPS в Европе: 30–60 мс.

## Поток подключения

```
клиент                     сервер                         ядро
  │  POST /api/v1/join       │
  │  {invite, name, pubkey}  │
  ├─────────────────────────►│  находит сеть по коду
  │                          │  выделяет свободный IP
  │                          │  awg set peer <pub> allowed-ips <ip>/32
  │◄─────────────────────────┤  {token, ip, awgPubKey, obfuscation, ports}
  │                          │
  │  генерирует conf, поднимает интерфейс через службу-помощник
  │  ping 10.66.0.1 ─────────┼───────────► handshake + ICMP
  │  POST /api/v1/heartbeat  │
  ├─────────────────────────►│  lastSeen
```

`join` идемпотентен по `deviceId`: переустановка клиента не плодит адреса.
Повторный вход тем же публичным ключом переиспользует слот.

## Мир Minecraft

Broadcast в L3-сети не проходит, поэтому «открыть для сети» недостаточно — нужен
явный обмен адресом:

1. Клиент читает `%APPDATA%\.minecraft\logs\latest.log` и ищет строку о порте,
   который игра открыла для LAN (`Started serving on <port>`).
2. Порт уходит на сервер в `POST /api/v1/heartbeat` (`lanPort`, 1025–65535);
   закрытие мира отправляет `lanPort: null` и стирает запись.
3. Сервер кладёт порт в `publicPeer()` — его видят все участники сети, а не
   только автор.
4. Друг нажимает «Зайти»: клиент дописывает `10.66.0.N:<port>` в
   `%APPDATA%\.minecraft\servers.dat` (gzip + NBT, незнакомые теги сохраняются,
   перед записью — `.nurofen.bak`) и копирует адрес в буфер.

Порт эфемерный: он меняется при каждом открытии мира, поэтому сервер хранит его
рядом с `lastSeen`, а не в отдельном реестре.

## Адресация

- `10.66.0.1` — хаб.
- `10.66.0.2–9` — резерв (DNS, будущий шлюз в интернет).
- `10.66.0.10–254` — устройства.
- Каждый клиент получает `Address = 10.66.0.N/24`: подсеть считается on-link,
  поэтому маршруты к друзьям не нужны.

## UDP-порты и обфускация

AmneziaWG слушает один порт (`server.awgPort`, выбирается случайным при
установке). Дополнительные порты из `server.portPool` (`443`, `500`, `4500`,
`8443`) заворачиваются на основной через `iptables -t nat`:

```
PREROUTING → NUROFEN_PORTS → REDIRECT --to-ports <awgPort>
```

Клиент перебирает адреса по порядку (`lastPort`, затем пул) и останавливается на
первом, где прошёл ping хаба. Так блокировка одного порта стоит одного лишнего
переподключения, а не всей сети.

Параметры обфускации (`Jc/Jmin/Jmax/S1/S2/H1..H4`) генерируются случайно при
создании конфига сервера: одинаковых установок не бывает, сигнатура одной не
работает против другой. Пересоздать: `node src/cli.js reseed` + перезапуск.

## Хранение состояния

`/etc/nurofen/nurofen.json` — единственный источник правды: токен админа, ключи
сервера, параметры обфускации, сети, устройства (публичные ключи, IP, хеши
токенов устройств). Файл пишется атомарно (tmp + rename), режим `0600`.

Сгенерированный `nurofen0.conf` перезаписывается сервером при каждом изменении
состава устройств, чтобы после перезагрузки интерфейс поднялся с актуальным
списком пиров.

## API

Публичное (по токену устройства):

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/join` | вход по коду приглашения |
| GET | `/api/v1/state` | список участников, статус туннеля |
| POST | `/api/v1/heartbeat` | отметка «я жив» + порт открытого мира (`lanPort`) |
| POST | `/api/v1/key` | смена публичного ключа |
| POST | `/api/v1/leave` | выйти и освободить адрес |

Админское (по `adminToken`):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/admin/overview` | сводка для панели |
| POST | `/api/v1/admin/invite/rotate` | сменить код приглашения |
| DELETE | `/api/v1/admin/peers/:id` | отключить устройство |
| POST | `/api/v1/admin/awg/restart` | перезапустить интерфейс |

`join` ограничен 10 попытками в минуту с одного IP, код приглашения — 40 бит
энтропии (8 символов из алфавита без похожих букв).

## Почему без зависимостей

Сервер и клиент используют только стандартную библиотеку Node.js. Это значит:
`git clone` + `node src/index.js` вместо `npm install`, нет supply-chain риска на
сервере, который держит ключи, и обновление — это `git pull`.
